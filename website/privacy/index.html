Privacy

01No accounts, no telemetry.

Keystore Studio collects no personal data. You don't sign in, and nothing reports back: the app contains no analytics, no advertising, no crash reporting and no update checker.

  • Accounts
  • Analytics
  • Telemetry
  • Crash reports
  • Update checks
  • Advertising

The app reads and writes only the files you open, save or export.

02What stays in memory.

Keystore contents and passwords are held in memory only. They reach disk solely in the keystore files you save. Passwords you don't store in the vault are forgotten when the app quits.

Saves are written atomically, then read back to verify them before they replace the original. Edits can be undone, and unsaved changes are guarded when you close a keystore or quit.

03What's written to disk.

The app keeps its own session state in an app data folder. No key material is stored there. It holds:

  • Settings, workspaces, labels, and the paths of recent and open files.
  • The certificates listed on the Certificates page (public certificates only).
  • The vault, if you set one up: remembered keystore passwords, encrypted (see below).
  • A record of the certificates you issue as a CA (serial number, subject, key identifiers and expiry date) and the last CRL number of each CA, so later CRLs can revoke them.

Set the environment variable KEYSTORE_STUDIO_DATA_DIR to keep this state somewhere else. A data folder left by the app under its former name, xkeystore, is moved to the new location on first start, so your vault, session and settings carry over.

04The vault.

The vault remembers keystore passwords under one master key, so keystores from your last session can reopen once you unlock it. It auto-locks after a period of inactivity.

DeriveArgon2idProduces the vault key
Seal each secretAES-256-GCMIts ID bound as associated data

  • The master key itself is never stored. The vault key is derived from it with Argon2id each time you unlock.
  • Each password is sealed on its own with AES-256-GCM, bound to its ID as associated data, so one sealed secret can't be swapped in for another.
  • Changing the master key re-encrypts every secret. If you forget it, you can reset the vault, which deletes the remembered passwords.

05Network requests.

Keystore Studio makes network requests in exactly four situations, and only when you start them. It makes no others.

  • Inspecting a TLS server

    In Examine, the app connects to the host and port you enter and performs a TLS handshake, the same way a browser or openssl s_client would, to show the protocol, cipher, chain and trust verdict.

    To the server you nameWhen you start an inspection

  • Testing a connection

    Also in Examine, a TCP connection test says whether a server port can be reached from your machine, and why not if it can't.

    To the host and port you nameWhen you run the test

  • Requesting an RFC 3161 timestamp

    When you turn on trusted timestamps for CMS or JAR signatures, the app sends a hash of what you signed to the timestamp authority you chose, with the app name and version as the user agent. The content itself and your keys are not sent.

    To the TSA you configureOnly when timestamps are on

  • Checking revocation online

    When you click Check revocation (OCSP) on a certificate chain, or tick Also check revocation online when validating one, the app asks the certificate's OCSP responder or downloads its CRL. That tells the CA which certificate is being checked (its serial number, for OCSP); your keys are not sent.

    To the CA's OCSP or CRL serverOnly when you ask

Commands in the built-in terminal run on your computer with your permissions. Anything they send over the network is up to the command you run, as in any other terminal.

Servers, timestamp authorities and CAs you contact handle those requests under their own privacy policies. On Windows, if WebView2 is missing, setup installs it: the published setup includes a copy, and a setup you build yourself downloads it from Microsoft. The app itself never does.

06Clipboard.

The app writes to the clipboard only when you copy something. Copy diagnostics includes the app version, platform, data folder, and the names and aliases of open keystores. Never passwords or key material.

07Hardening.

A strict Content Security Policy

The interface runs in a webview that may load only the app's own scripts and styles, and may talk only to the Rust engine over Tauri's IPC channel. It cannot reach the internet. The policy, as shipped:

default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; connect-src ipc: http://ipc.localhost; object-src 'none'; base-uri 'self'; form-action 'none'; frame-ancestors 'none'

Fuzzed parsers

Every parser is fed malformed input in the test suite (truncations, bit flips, forged length headers of real keystores, deep nesting) and must return an error rather than crash. Coverage-guided fuzz targets run as a smoke test in CI.

Dependency checks

cargo deny checks every Rust dependency for security advisories, licences and sources in CI.

Every crypto operation is local

Keys are generated, parsed, signed with and converted in the bundled Rust engine. Java and OpenSSL are not needed; the app only refers to them for the terminal and the equivalent commands it shows you.

08Your control.

  • Settings → Data → Reset app data clears settings, workspaces, labels, recent files and the Certificates list.
  • Records of issued certificates are deleted one by one in CA & Signing.
  • Resetting the vault on the Vault page deletes the remembered passwords.
  • Deleting the data folder removes everything Keystore Studio keeps. Uninstalling the app leaves it in place.

09This website.

This site is a set of static pages. It sets no cookies, runs no analytics, and makes no requests to third parties: no web fonts, no CDNs, no embeds, no trackers. Every file it loads comes from the same place as the page.

The site asks before it remembers anything. If you accept and then pick a light or dark theme with the toggle in the header, your browser's local storage keeps that choice under the key ks-theme; choosing the automatic theme removes it. If you decline, the theme isn't saved. Your answer itself is kept under ks-consent, so the question isn't repeated. Neither leaves your browser, and clearing this site's data removes both.

The server that hosts the site may keep standard access logs, as web servers do. Links to GitHub, rustup and other sites take you to services with their own privacy policies.

10Questions.

Keystore Studio is open source, so you can check every statement on this page against the code. The app's own privacy policy, in Settings, changes in the same release as any code that changes what it stores or sends.

Questions or concerns: open an issue on GitHub, or send us a message.
